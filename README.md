# Карта изучения программирования

Карта-навигатор по программированию на Python для школьников. Спецификация — задача №1 в трекере.

## Запуск

Нужен Node.js 22 или новее.

```bash
npm install
npm run dev
```

Сайт откроется по адресу http://localhost:5173. Правки файлов карты сразу видны на странице.

## Данные карты

Лежат в `data/map`:

- `sections/*.yaml` — по файлу на раздел. Раздел — крупная группа тем, объединённых умением (ADR 0003); связи между разделами не должны образовывать петель. Разделы идут в порядке имён файлов, поэтому имена начинаются с номера (`01-…`, `02-…`). Узлы внутри раздела идут в порядке, в котором записаны.
- `goals.yaml` — цели и их ступени. Ступень задаётся списком целевых узлов.

Узел описывается так:

```yaml
- id: digits-of-number          # постоянный идентификатор; не менять после публикации
  kind: topic                   # topic — тема, ege-task — задание ЕГЭ
  title: Цифры числа
  description: Разбор числа на цифры с помощью деления и остатка в цикле.
  prerequisites: [while-loop, input-numbers]
  materials:
    - title: Название материала
      url: https://…
  checkTasks:
    - title: Название задачи
      url: https://…
```

У задания ЕГЭ есть ещё `egeNumber` — номер задания. Он только подпись, и его можно менять. Пустые списки можно не писать.

## Настройки сайта

Лежат в файле `.env` в корне проекта.

- `VITE_REPORT_URL` — адрес канала для сообщений об ошибках (форма или чат без регистрации). Вместо `{узел}` в адрес подставляется название узла. Пока адрес пуст, ссылки «Сообщить об ошибке» в панели узла нет.

## Проверки

```bash
npm run check:data  # проверка данных карты: ошибки и предупреждения
npm test            # тесты ядра логики карты
npm run test:e2e    # сквозные тесты собранного сайта в браузере (на своей учебной карте из tests/e2e/map)
npm run build       # проверка типов и сборка сайта в dist/
npm run check:links # проверка ссылок (см. ниже)
```

Проверка данных завершается с ошибкой, если в карте есть хотя бы одна блокирующая ошибка (повтор идентификатора, несуществующий узел, цикл в пререквизитах, разделы, опирающиеся друг на друга по кругу); предупреждения на это не влияют. Другую карту можно проверить, указав её каталог: `npm run check:data -- tests/e2e/map`.

Перед первым запуском `test:e2e` нужно один раз поставить браузер: `npx playwright install chromium`. Сквозные тесты сначала собирают сайт (в `dist-e2e/`) и открывают его из подкаталога `/PythonMap/`, как на GitHub Pages.

## Проверка ссылок

```bash
npm run check:links
```

Открывает каждую ссылку на материалы и контрольные задачи и печатает по каждой: узел, название ссылки и открылась ли страница. Соответствие содержания узлу скрипт не проверяет. Запускайте его перед публикацией правок. Ручной запуск ничего не сохраняет: счёт неудач подряд он берёт из истории еженедельных проверок и прибавляет к нему свою неудачу.

Раз в неделю, по понедельникам, тот же скрипт запускается в GitHub Actions (`.github/workflows/links.yml`). На вкладке Actions его можно запустить и вручную кнопкой Run workflow: такой запуск обновляет задачу в трекере, но в историю неудач не записывается. Часть сайтов отвечает отказом на автоматические запросы, поэтому ссылка считается мёртвой только после нескольких неудач подряд в еженедельных проверках. Число неудач задано в `tools/link-history.ts` (`DEAD_AFTER_FAILURES`, сейчас 3), а история неудач хранится в `data/link-failures.json` — её обновляет и сохраняет в репозиторий сам еженедельный запуск.

Мёртвые ссылки собираются в одну задачу трекера «Мёртвые ссылки на карте» с меткой «проверка ссылок». Пока она открыта, следующие запуски обновляют её, а не заводят новую; когда мёртвых ссылок не остаётся, в ней появляется запись об этом, а закрываете задачу вы. Если мёртвых ссылок нет, задача не заводится. На сайте мёртвая ссылка не скрывается.

## Публикация

Сайт — набор статических файлов, сервер ему не нужен. Публикует его GitHub Actions (`.github/workflows/site.yml`):

- при каждом изменении в `main` и в каждом запросе на слияние запускаются все проверки из списка выше;
- если это `main` и все проверки прошли, собранный сайт публикуется на GitHub Pages (адрес — в Settings → Pages);
- блокирующая ошибка в данных останавливает публикацию; предупреждения видны в журнале запуска и пометками на его странице.

Ход и итог запусков — на вкладке Actions репозитория.

Один раз владелец репозитория включает публикацию: Settings → Pages → Build and deployment → Source: **GitHub Actions**.

До подключения собственного домена адрес сайта ученикам не объявляется: прогресс привязан к адресу и при его смене пропадёт (ADR 0001).

## Устройство

- `src/core` — ядро логики карты: все правила, без зависимостей от интерфейса и браузера.
- `src/layout` — раскладка графа на экране.
- `src/app` — интерфейс на React.
- `tools` — чтение файлов карты с диска и подключение их к сборке.
